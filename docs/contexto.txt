## Entrada Principal
-src/App.jsx
Es el componente raíz de la aplicación. Envuelve toda la app con AutoProvider, para que cualquier componente pueda saber si hay usuario autenticado, y renderiza AppRoutes, odnde vive la navegación

## Rutas
-src/app/routes.jsx
Define las rutas principales
    /auth: pantalla de login/registro.
    /dashboard: vista inicial de planeaciones.
    /perfil: formulario del perfil docente.
    - Protege las rutas internas usando ProtectedRoute
    -Si alguien entra sin sesión, lo manda a /auth


## Autenticación
-src/features/auth/hooks/AuthProvider.jsx
    Mantiene el estado global de autenticación:
        -Lee la sesión actual de supabase
        -Escucha cambios de login/logout
        -Guarda session, user y loading
        -Es el "cerebro" de la sesión
-src features/auth/hooks/authContext.js
    Crea el contexto de React para compartir la sesión en toda la app
-src/features/auth/hooks/useAuth.js
    Es un hook cómodo para consumir la sesión: const {user, session, loading } = useAuth()
    Así evitamos pasar datos manuales entre componentes
-src/features/auth/services/authService.js
    Centraliza las acciones de Supabase Auth:
        signInWithEmail
        signUpWithEmail
        signOut
    Esto evita poner lógica de Supabase directamente dentro de los componentes
-src/features/auth/pages/AuthPage.jsx
    Pantalla de inicio de sesión y registro
    Usa:
        -react-hook-form para manejar el formulario
        -zod para validar correo y contraseña
        -Supabase Auth para registrar o iniciar sesión

## Rutas Protegidas
-src/components/common/ProtectedRoute.jsx

## Página Crear/Editar
-src\features\planners\pages\PlannerFormPage.jsx
    Es la página que envuelve al formulario.
    Hace esto:
    - Detecta si estás creando o editando usando el parámetro id de la URL.
    - Carga las materias y grupos del perfil docente.
    - Si estás editando, carga la planeación existente.
    - Convierte los datos de Supabase al formato que espera el formulario.
    - Al guardar:
    - Si es nueva, llama a createPlanner.
    - Si es edición, llama a updatePlanner.
    - Redirige al dashboard cuando guarda correctamente.
    También valida que el usuario tenga materias y grupos antes de permitir crear planeaciones.

## Esquema de validación
-src\features\planners\schemas\plannerSchema.js
    Valida:
    - Fechas generales obligatorias.
    - Fecha final mayor o igual a fecha inicial.
    - Materia obligatoria.
    - Grupo obligatorio.
    - Contenido obligatorio.
    - PDA obligatorio.
    - Propósito obligatorio.
    - Al menos una secuencia didáctica.
    - Cada secuencia debe tener:
    - Fechas.
    - Inicio.
    - Desarrollo.
    - Cierre.
    - Las fechas de cada secuencia deben estar dentro del rango general de la planeación.
    También exporta plannerDefaultValues, que son los valores iniciales del formulario.

## Servicio de Planeaciones
-src\features\planners\services\plannerService.js
    Centraliza toda la comunicación con Supabase para planeaciones.
    Incluye:
    - listPlanners(userId): obtiene las planeaciones del docente.
    - getPlannerById(id): obtiene una planeación con sus secuencias.
    - createPlanner(userId, values, catalogs): crea una planeación y sus secuencias.
    - updatePlanner(id, userId, values, catalogs): actualiza la planeación y reemplaza sus secuencias.
    - deletePlanner(id): elimina una planeación.
    También tiene funciones internas para transformar los datos del formulario al formato de la base de datos.

  siguiente fase recomendada sería robustez de datos en Supabase:

  Antes, al crear/editar una planeación, el frontend hacía varias operaciones separadas: guardar planners, borrar/insertar didactic_sequences, etc. Ahora esas operaciones se ejecutan dentro de funciones SQL en Supabase, en una sola transacción. Si falla una parte, no queda una planeación guardada a medias.
Cambios realizados:
- [docs/supabase-rpc-planners.sql](C:/Users/yael.garay/Documents/PERSONAL/Proyectos-web/planeaciones-app-codex/planeaciones-app/docs/supabase-rpc-planners.sql)
  - Agregué el script SQL con dos funciones:
    - create_planner_with_sequences
    - update_planner_with_sequences
  - Ambas usan auth.uid() para identificar al usuario autenticado.
  - Validan que la materia y el grupo pertenezcan al usuario.
  - Guardan la planeación y sus secuencias de forma atómica.
  - Incluyen permisos grant execute para usuarios autenticados.
- [plannerService.js](C:/Users/yael.garay/Documents/PERSONAL/Proyectos-web/planeaciones-app-codex/planeaciones-app/src/features/planners/services/plannerService.js)
  - Cambié createPlanner para usar:supabase.rpc('create_planner_with_sequences')
  - Cambié updatePlanner para usar:supabase.rpc('update_planner_with_sequences')
  - El frontend ya no manda user_id, subject_name ni group_label.
  - Supabase calcula esos datos de forma segura desde la sesión y los catálogos del usuario.
Importante: para que crear/editar vuelva a funcionar, debes ejecutar el SQL de [supabase-rpc-planners.sql](C:/Users/yael.garay/Documents/PERSONAL/Proyectos-web/planeaciones-app-codex/planeaciones-app/docs/supabase-rpc-planners.sql) en el SQL Editor de Supabase.
